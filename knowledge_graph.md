# TeamOS — Knowledge Graph Module

**Status:** Partial  
**Capability refs:** `GRA-001`, `GRA-002`, `GRA-003`, `GRA-004` in `docs/capability-matrix.md`

## Current behavior

- Graph retrieval, node detail, analytics, hubs/orphans, and manual edge APIs are implemented.
- Graph visualization surface exists in frontend and is wired to backend analytics payloads.
- Core graph wiring from wiki/ingest exists.
- Advanced semantic clustering quality and richer graph semantics are still partial.

## Target behavior

- Higher-fidelity clustering/communities with stable and explainable semantics.
- Stronger citation edge semantics and edge-level context actions in UI.
- Clear mode/version visibility between simple vs advanced analytics behavior.
- Better validation and benchmarked quality for inferred relationships at scale.

The Knowledge Graph is the associative brain of TeamOS. It moves beyond simple folder structures to create a dense network of relationships between concepts, documents, and entities.

---

## 1. Associative Architecture

The graph is modeled as a **Directed Multigraph** stored in PostgreSQL and visualized via **Cytoscape.js**. 

### Edge Types
*   **Wikilink**: Manual connections created by users using `[[Page Title]]`.
*   **Semantic Similarity**: AI-inferred connections generated by the **Vector Engine**. These link conceptually related pages (e.g., "Quantum Computing" → "Physics") even if they share no keywords.
*   **Citation**: Grounded links that point from a synthesis page back to a raw data source or another wiki page.
*   **Manual**: Explicit relationships drawn by users in the Graph UI.

---

## 2. The Vector Engine (Semantic Inference)

Instead of "dumb" keyword matching, TeamOS uses high-fidelity semantic inference:
1.  **Embedding**: Every page chunk is converted into a 1536-dimensional vector.
2.  **Vector Search**: The system queries **Qdrant** to find pages with the highest "Conceptual Proximity."
3.  **Inference Task**: A background Celery task (`infer_ai_edges`) continuously refreshes these connections as the wiki evolves.

---

## 3. Graph Analytics & Community Detection

TeamOS performs real-time analytics to help teams understand their knowledge distribution:
*   **PageRank**: Identifies "Knowledge Hubs"—the most influential pages in the team's brain.
*   **Community Detection**: Clusters pages into thematic groups (e.g., "Engineering," "Marketing," "Project Alpha") using connectivity analysis.
*   **Orphan Detection**: Highlights documents that are isolated from the graph, suggesting gaps in documentation or linking.

---

## 4. The Graph UI (Interactive Explorer)

The frontend provides a premium, futuristic interface for exploring the graph:
*   **Dynamic Layout**: Uses a force-directed layout that reacts to user interaction.
*   **Filtering**: Toggle between manual wikilinks and AI-inferred semantic edges.
*   **Deep Navigation**: Clicking a node selects the page; double-clicking opens the **Full Editor**.
*   **Edge Context**: Hovering over an edge shows the "Reasoning" or "Confidence Score" for AI-inferred relationships.

---

## 5. Technical Implementation

*   **Database**: `GraphEdge` model in PostgreSQL with indices on `from_page` and `to_page`.
*   **Vector DB**: **Qdrant** handles the semantic similarity searches.
*   **Backend Logic**: `backend/graph_engine/analytics.py` (PageRank, Clusters).
*   **Worker Tasks**: `backend/ingest/tasks.py` (Relationship Inference).
